## Описание

`/init` — начальный процесс платформы PUNos. Ядро Linux запускает его из
initramfs как первый userspace-процесс с PID 1. Он подготавливает обязательные
виртуальные файловые системы, создаёт runtime-каталоги и запускает `initserv`.

`/init` не является System Service и не выполняет обязанности initserv.
Начальный процесс владеет жизненным циклом initserv, а initserv владеет
PlatformRegistry и жизненным циклом остальных System Services.

Формат и состав архива, содержащего `/init`, описаны отдельно в документе
[initramfs](initramfs.md).

## Имя компонента

| Поле | Значение |
| --- | --- |
| Путь | `/init` |
| Тип | Начальный процесс платформы |
| PID | `1` |
| Владелец запуска | Ядро Linux |
| Дочерний системный компонент | `/punos/bin/initserv` |
| IPC endpoint | Не предоставляет в v1 |

## Ответственность и границы

- `/init` проверяет, что запущен как PID 1.
- `/init` монтирует обязательные виртуальные файловые системы.
- `/init` создаёт runtime-каталог `/run/punos` после монтирования `/run`.
- `/init` запускает только `/punos/bin/initserv` по фиксированному пути.
- `/init` сохраняет владение дочерним процессом initserv и освобождает
  завершившиеся дочерние процессы.
- `/init` сообщает об ошибках ранней загрузки напрямую через console.
- `/init` не читает PlatformRegistry и не запускает остальные System Services.
- `/init` не предоставляет IPC API и не обслуживает приложения.
- `/init` не возвращается из `main()` и не завершает PID 1 через обычный
  `exit()`.

## Формат исполняемого файла

- ELF64 для Linux x86_64.
- Статическая линковка без ELF-интерпретатора `PT_INTERP`.
- Точка входа `_start` из CRT PUNos.
- Отсутствие зависимости от glibc и других библиотек host-системы.
- Права в initramfs `0755`.

## Зависимости

| Зависимость | Использование |
| --- | --- |
| CRT | Вход `_start` и передача управления в `main()` |
| Syscall Wrappers | `getpid()`, `mount()`, `mkdir()`, `open()`, `write()`, `close()`, `fork()`, `execve()`, `waitpid()` и `nanosleep()` |

`/init` не использует System Libs, Special Libs, IPC и System Services. Это
сохраняет раннюю загрузку независимой от компонентов, которые она должна
запустить.

Syscall Wrapper `mount()` является обязательной частью boot-набора. Для
будущего штатного выключения потребуется отдельный wrapper `reboot()`, который
в v1 ещё не определён.

## Последовательность запуска

1. CRT передаёт управление в `main()` начального процесса.
2. `/init` вызывает `getpid()` и проверяет значение `1`.
3. `/init` подготавливает обязательные виртуальные файловые системы.
4. `/init` повторно создаёт `/run/punos` после монтирования tmpfs на `/run`.
5. `/init` создаёт дочерний процесс.
6. Дочерний процесс вызывает `execve()` для `/punos/bin/initserv`.
7. Родительский PID 1 периодически вызывает `waitpid(-1, ..., WNOHANG)`,
   освобождает всех завершившихся детей и отдельно отслеживает завершение
   initserv.

Успешный `execve()` означает только передачу управления initserv. Готовность
System Services определяется контрактом initserv и не проверяется `/init`.

## Виртуальные файловые системы

| Порядок | Источник | Точка | Тип | Обязательность |
| --- | --- | --- | --- | --- |
| 1 | `devtmpfs` | `/dev` | `devtmpfs` | Критично |
| 2 | `proc` | `/proc` | `proc` | Критично |
| 3 | `sysfs` | `/sys` | `sysfs` | Критично |
| 4 | `tmpfs` | `/run` | `tmpfs` | Критично |
| 5 | `tmpfs` | `/tmp` | `tmpfs` | Некритично в v1 |

Ошибка критичного mount запрещает запуск initserv. Начальный процесс выводит
название точки монтирования и код ошибки в console, переходит в состояние
`Failed` и остаётся живым для сохранения диагностического вывода.

После монтирования tmpfs на `/run` исходное содержимое каталога из initramfs
перестаёт быть видимым. Поэтому `/init` обязан создать `/run/punos` после
успешного mount `/run`.

## Жизненный цикл

| Состояние | Допустимые действия | Переходы |
| --- | --- | --- |
| Starting | Проверка PID, mount виртуальных файловых систем, подготовка runtime-каталогов | StartingInitserv, Failed |
| StartingInitserv | Создание процесса и `execve()` initserv в дочернем процессе | Running, Failed |
| Running | Неблокирующий `waitpid()` для initserv и переподчинённых детей, ожидание через `nanosleep()` | Failed, Stopping в будущей версии |
| Failed | Вывод ошибки в console и бесконечное ожидание | Нет переходов в v1 |

В v1 автоматический перезапуск initserv не выполняется: политика перезапуска
начального системного сервиса должна быть определена отдельно. Завершение
initserv переводит `/init` в `Failed`.

## Владение ресурсами

| Ресурс | Владелец | Создание | Освобождение |
| --- | --- | --- | --- |
| PID 1 | `/init` | Ядро Linux | Только при остановке системы |
| Точки монтирования | `/init` | Во время Starting | При будущем штатном выключении |
| Дочерний PID initserv | `/init` | После `fork()` | Через `waitpid()` |
| `/run/punos` | `/init` | После mount `/run` | Вместе с tmpfs `/run` |
| Console-дескриптор | `/init` | При начале диагностики | После вывода сообщения |

`/init` не передаёт владение PID initserv другому процессу и не запускает
второй экземпляр, пока первый не освобождён через `waitpid()`.

## Работа PID 1

Начальный процесс обязан освобождать не только непосредственно запущенный
initserv, но и осиротевшие процессы, переподчинённые PID 1 после завершения их
родителя. Он повторяет `waitpid(-1, ..., WNOHANG)`, пока wrapper возвращает
положительный PID, и не считает отсутствие готовых детей ошибкой.
Zombie-процессы не должны накапливаться.

Обычные правила сигналов Linux для PID 1 отличаются от правил остальных
процессов. Обработка выключения и управляющих сигналов должна быть определена
явно до появления состояния `Stopping`.

## Логирование и наблюдаемость

До запуска logserv начальный процесс пишет только короткие диагностические
сообщения в `/dev/console`. Сообщение содержит этап и числовой код ошибки, но
не использует динамическую память или форматирование общего назначения.

После запуска initserv начальный процесс не отправляет IPC-сообщения в logserv
в v1. Его состояние наблюдается только через console и факт существования PID
1.

## Ошибки

| Ошибка | Реакция v1 |
| --- | --- |
| `/init` запущен не как PID 1 | Сообщение в console, состояние `Failed` |
| Не удалось смонтировать `/dev`, `/proc`, `/sys` или `/run` | Сообщение в console, initserv не запускается |
| Не удалось создать `/run/punos` | Сообщение в console, initserv не запускается |
| Не удалось смонтировать `/tmp` | Предупреждение в console, загрузка продолжается |
| `fork()` завершился ошибкой | Сообщение в console, состояние `Failed` |
| `/punos/bin/initserv` отсутствует или `execve()` завершился ошибкой | Сообщение в console, состояние `Failed` |
| Initserv завершился | Освобождение процесса, сообщение в console, состояние `Failed` |
| `waitpid()` завершился неисправимой ошибкой | Сообщение в console, состояние `Failed` |

## Ограничения версии

- Нет штатного выключения или перезагрузки.
- Нет автоматического перезапуска initserv.
- Нет IPC API для состояния ранней загрузки.
- Нет интерактивной аварийной оболочки.
- Нет переключения на постоянную rootfs.
- Поддерживается только Linux x86_64 в QEMU.
