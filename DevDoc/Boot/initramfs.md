## Описание

Initramfs — начальная файловая система PUNos, которую QEMU передаёт ядру Linux
вместе с `bzImage`. Ядро распаковывает initramfs в память, использует его как
первую корневую файловую систему и запускает находящийся в ней `/init`.

Initramfs является загрузочным артефактом PUNos, а не частью исходного кода
ядра. Ядро Linux не изменяется и не содержит компоненты PUNos внутри своего
дерева исходников.

Контракт исполняемого файла `/init`, его жизненный цикл и зависимости описаны
отдельно в документе [init](init.md).
Пошаговые команды для подготовки чистого клона, сборки и запуска в QEMU
находятся в [руководстве системного слоя](../../System/README.md).

## Текущий статус реализации

Сборщик initramfs реализован. Он собирает CRT, Syscall Wrappers, `/init` и
временный initserv smoke-test stub, проверяет ELF64 x86_64 и отсутствие
`PT_INTERP`, формирует staging rootfs с заданными правами и создаёт
воспроизводимый `newc`+gzip архив. Две последовательные сборки с одинаковыми
входами обязаны давать одинаковый SHA-256.

Проверочный образ также содержит `/punos/bin/syscall-selftest`. Временный
initserv stub запускает его один раз и сообщает результат. Этот файл является
тестом системного ABI и не относится к составу будущего production-образа.

Архив успешно проверен загрузкой в QEMU: ядро запустило `/init` как PID 1,
обязательные виртуальные файловые системы были смонтированы, а initserv stub —
запущен через `fork()`/`execve()`. Настоящий initserv и остальные System
Services в образ пока не входят.

## Назначение и границы

- Initramfs предоставляет ядру начальную структуру каталогов и исполняемый
  файл `/init`.
- Initramfs содержит статически собранные ELF-файлы Linux x86_64, данные
  конфигурации и заранее созданные каталоги PUNos.
- Initramfs определяет расположение компонентов, права файлов и правила
  формирования воспроизводимого архива.
- Initramfs не определяет внутреннее устройство CRT, Syscall Wrappers,
  System Libs или System Services.
- Initramfs не изменяет ABI ядра, не добавляет системные вызовы и не содержит
  kernel modules в v1.
- Initramfs не является постоянным хранилищем. Изменения его файлов теряются
  после выключения виртуальной машины.
- Сборка initramfs не использует файлы, библиотеки или конфигурацию host-системы,
  кроме явно зафиксированных инструментов сборки.

## Место в последовательности загрузки

| Порядок | Компонент | Действие |
| --- | --- | --- |
| 1 | QEMU | Загружает `bzImage` и архив initramfs в память виртуальной машины |
| 2 | Linux | Инициализирует процессоры, память и встроенные драйверы |
| 3 | Linux | Распаковывает initramfs и назначает его первой rootfs |
| 4 | Linux | Находит `/init` и запускает его как PID 1 |
| 5 | `/init` | Продолжает загрузку согласно отдельному контракту начального процесса |

Отсутствие `/init`, неверные права доступа или неподдерживаемый формат
исполняемого файла являются фатальной ошибкой загрузочного образа.

## Формат артефакта

Initramfs v1 представляет собой архив `cpio` в формате `newc`, сжатый gzip:

```text
punos-initramfs.cpio.gz
```

Архив передаётся QEMU отдельным аргументом `-initrd`. Он не встраивается в
`bzImage`, чтобы ядро и userspace можно было пересобирать и проверять
независимо.

Все пути в архиве относительные, не содержат `..` и после распаковки находятся
внутри первой rootfs. Все объекты v1 принадлежат `uid=0`, `gid=0`. Сборка
нормализует порядок путей и временные метки, чтобы одинаковые входные файлы
создавали одинаковый архив.

## Текущий проверочный состав

Реализованный development-образ содержит только компоненты, необходимые для
проверки границы передачи следующему слою:

```text
/
├── init
├── dev/
├── proc/
├── sys/
├── run/
├── tmp/
├── var/
│   └── log/
│       └── punos/
└── punos/
    ├── bin/
    │   ├── initserv          # временный smoke-test stub
    │   └── syscall-selftest  # только development-образ
    ├── apps/
    └── config/
```

Настоящие System Services и приложения в текущую сборку не входят.

## Целевой production-состав v1

После интеграции следующего слоя smoke-test stub заменяется настоящим
`initserv`, `syscall-selftest` удаляется, а сборка размещает сервисы из
PlatformRegistry:

```text
/
├── init
├── dev/
├── proc/
├── sys/
├── run/
├── tmp/
├── var/
│   └── log/
│       └── punos/
└── punos/
    ├── bin/
    │   ├── initserv
    │   ├── logserv
    │   ├── appserv
    │   └── другие включённые System Services
    ├── apps/
    └── config/
```

| Путь | Назначение | Права v1 |
| --- | --- | --- |
| `/init` | Начальный исполняемый файл | `0755` |
| `/dev` | Точка для файловой системы устройств | `0755` |
| `/proc` | Точка для информации о процессах и ядре | `0555` |
| `/sys` | Точка для модели устройств ядра | `0555` |
| `/run` | Точка для временных runtime-данных | `0755` |
| `/tmp` | Временные файлы процессов | `01777` |
| `/var/log/punos` | Журналы PUNos в v1 | `0755` |
| `/punos/bin` | Нативные компоненты платформы | `0755` |
| `/punos/apps` | Встроенные приложения | `0755` |
| `/punos/config` | Статическая конфигурация образа | `0755` |

Файлы в `/punos/bin`, `/punos/apps` и `/punos/config` не изменяются во время
работы v1. Журналы в `/var/log/punos` являются временными до появления
постоянной rootfs.

## Требования к исполняемым файлам

Каждый исполняемый файл, помещаемый в initramfs, обязан быть:

- ELF64 для Linux x86_64;
- статически скомпонованным;
- не содержащим ELF-интерпретатор `PT_INTERP`;
- не зависящим от библиотек host-системы;
- исполняемым владельцем root.

Внутренняя точка входа, runtime и библиотечные зависимости конкретного файла
определяются документацией соответствующего компонента, а не контрактом
initramfs.

## Контракт сборки

1. Сборка начинается из пустого staging-каталога rootfs.
2. Все каталоги создаются с явно заданными правами.
3. Компоненты копируются только после успешной сборки и проверки.
4. Текущая development-сборка завершается ошибкой, если `/init`, initserv stub
   или `syscall-selftest` отсутствует. Production-сборка дополнительно обязана
   проверять все включённые в PlatformRegistry System Services.
5. Сборка проверяет тип, архитектуру и отсутствие `PT_INTERP` у каждого ELF.
6. После интеграции PlatformRegistry пути production-сервисов должны точно
   совпадать с путями реестра. Текущий builder реестр ещё не читает.
7. Архив создаётся только после успешной проверки полного staging-каталога.
8. Staging-каталог и готовый архив являются генерируемыми артефактами и не
   хранятся в Git.
9. Версия и checksum ядра, входные файлы и параметры архивации фиксируются в
   репозитории. Host-инструменты v1 перечислены в руководстве и проверены на
   Debian 13, но их точные версии пока не зафиксированы.

## Контракт запуска в QEMU

QEMU получает отдельно собранное ядро и initramfs:

```text
-kernel System/linux-build/arch/x86/boot/bzImage
-initrd <путь к punos-initramfs.cpio.gz>
-append "console=ttyS0,115200 rdinit=/init"
```

Параметр `rdinit=/init` явно фиксирует начальный процесс initramfs. Отсутствие
этого параметра допустимо для Linux, но не используется воспроизводимым
сценарием PUNos.

Успешная передача управления из initramfs подтверждается следующими событиями:

1. Ядро сообщает версию `6.12.111-punos`.
2. Ядро распаковывает initramfs без ошибки.
3. Ядро находит и запускает `/init`.
4. `/init` сообщает о начале userspace-загрузки PUNos.

Дальнейшие критерии успешной загрузки принадлежат контракту `/init`.

## Постоянные данные и развитие

Initramfs v1 целиком находится в оперативной памяти. Журналы, runtime-файлы и
любые изменения исчезают после остановки QEMU.

Целевой production-образ v1 должен содержать весь системный userspace,
необходимый для запуска PUNos. Текущий development-образ содержит только
проверочный boot-срез, описанный выше. Появление постоянной rootfs является
отдельной версией загрузочного контракта. После этого initramfs может быть
сокращён до среды ранней загрузки, которая обнаруживает, проверяет и монтирует
основную rootfs.

Конкретный формат диска, файловая система, переключение rootfs, схема
обновлений и восстановление не определены в v1.

## Ошибки образа

| Ошибка | Результат |
| --- | --- |
| Архив повреждён или имеет неподдерживаемый формат | Ядро не может распаковать initramfs |
| `/init` отсутствует | Ядро не может запустить userspace |
| `/init` не имеет права исполнения | Запуск начального процесса завершается ошибкой |
| ELF имеет неверную архитектуру | Ядро отклоняет исполняемый файл |
| ELF содержит отсутствующий динамический интерпретатор | Запуск компонента завершается ошибкой |
| Путь PlatformRegistry отсутствует в production-архиве | После интеграции реестра сборка initramfs завершается ошибкой |

## Ограничения версии

- Нет постоянной rootfs и сохранения данных между запусками.
- Нет проверки цифровой подписи содержимого initramfs во время загрузки.
- Нет kernel modules и загрузки firmware из initramfs.
- Нет выбора нескольких системных образов или отката обновления.
- Поддерживается только Linux x86_64 в QEMU.
