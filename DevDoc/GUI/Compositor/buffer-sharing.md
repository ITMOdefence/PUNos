# Передача графических буферов

## Решение

Целевой транспорт v1 использует разделяемую память и передачу файлового
дескриптора через Unix socket (`SCM_RIGHTS`). Обычный IPC payload содержит
только метаданные буфера. Пиксели через очередь `ipclib` не копируются.

```text
BufferDescriptor
├── BufferId id
├── u32 width
├── u32 height
├── u32 stride
├── PixelFormat format
├── u64 byte_size
└── received fd
```

## Владение

- Клиент создаёт backing storage, задаёт его размер и передаёт дубликат FD.
- `compositorserv` импортирует FD, проверяет метаданные и создаёт `BufferId`.
- Передача FD не передаёт право менять метаданные после импорта.
- Клиент не изменяет содержимое после commit до `buffer_released`.
- `compositorserv` закрывает свой FD после destroy, отключения клиента или
  окончательного освобождения буфера.
- `displayserv` получает только временную ссылку на готовый кадр от
  `compositorserv`; долгосрочное владение остаётся у compositor.

## Проверки

Сервис проверяет ненулевые размеры, поддерживаемый формат, минимальный stride,
переполнение `stride * height`, соответствие `byte_size` и фактического размера
объекта. Исполняемое отображение запрещено. Ошибка импорта не создаёт
`BufferId` и закрывает полученный FD.

## Требование к системному слою

До реализации протокола системная команда должна предоставить:

1. Syscall wrappers для `sendmsg()` и `recvmsg()` с безопасными ABI-типами.
2. Передачу ровно ограниченного числа FD в `ipclib`.
3. Закрытие всех непотреблённых FD при ошибке кадра или отключении.
4. Ограничение размера ancillary data и защиту от утечки FD.

Если эта возможность временно отсутствует, допустим только тестовый backend с
копированием небольших кадров. Он не является публичным контрактом GUI v1.
