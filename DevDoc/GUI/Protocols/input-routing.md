# Маршрутизация ввода

## Граница с системным слоем

`IOserv` публикует `IoInputFrameEvent` без преобразования кодов устройств.
`windowserv` подписывается на классы keyboard, pointer и touch и является
единственным GUI-компонентом, который выбирает получателя события.

```text
IOserv InputFrame
  → нормализация координат и состояния в windowserv
  → hit testing / keyboard focus / pointer capture
  → WindowInputEvent
  → uilib
  → widget event dispatch
```

## Правила маршрутизации

1. Клавиатурное событие получает окно с keyboard focus.
2. Pointer motion получает окно под указателем, кроме активного pointer grab.
3. Нажатие кнопки активирует верхнее допускающее фокус окно под указателем.
4. Touch sequence закрепляется за окном, получившим первое касание, до конца
   последовательности.
5. Модальное окно блокирует ввод в окна своей группы, расположенные ниже него.
6. Скрытое, минимизированное или уничтожаемое окно ввод не получает.
7. `windowserv` переводит глобальные координаты в локальные координаты окна.
8. `uilib` выполняет hit testing виджетов внутри клиентской области.

## Разделение ответственности

`IOserv` не знает об окнах. `windowserv` не преобразует клавиши в текст и не
реализует раскладки. Текстовый ввод и compose/IME оформляются отдельным
протоколом после v1. Toolkit не получает сырые device id, если приложение не
запросило диагностическое расширение.
