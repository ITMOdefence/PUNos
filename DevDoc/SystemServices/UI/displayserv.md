## Контракты

1. Все ошибки передаются как `ErrorCode` из `libcore`.
2. `CORE_OK` — единственный успешный результат.
3. Сервис не блокирует IPC event loop длительными операциями.
4. При отключении клиента освобождаются его сессии, подписки и временные ресурсы.
5. Внутренние handle и файловые дескрипторы не выдаются клиенту без отдельного контракта.
6. Входные данные проверяются до выполнения операции.
7. `<предметные инварианты сервиса>`.

## Ошибки

| `ErrorCode` | Когда возвращается |
| --- | --- |
| `CORE_INVALID_ARGUMENT` | Некорректное поле запроса |
| `CORE_INVALID_STATE` | Операция недопустима в текущем состоянии |
| `CORE_PERMISSION_DENIED` | У клиента нет разрешения |
| `CORE_NOT_FOUND` | Объект, сессия или ресурс не найдены |
| `CORE_IO_ERROR` | Ошибка устройства, файла или IPC |
| `CORE_OUT_OF_MEMORY` | Нельзя выделить память или создать сессию |
| `CORE_UNSUPPORTED` | Возможность не поддерживается |
