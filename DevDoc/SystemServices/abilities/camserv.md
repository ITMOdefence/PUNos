## Описание

camserv — системный сервис захвата изображения с одной камеры Linux. Он
открывает явно настроенное устройство `/dev/video*` через camlib, запускает
поток захвата с фиксированной конфигурацией и публикует сырые кадры доверенным
системным клиентам через локальный IPC.

## Имя сервиса

| Поле | Значение |
| --- | --- |
| Идентификатор | camserv |
| Исполняемый файл | camserv |
| Владелец запуска | initserv |
| IPC endpoint | /run/punos/camserv.sock |
| Версия протокола | v1 |

## Ответственность и границы

- camserv открывает только путь камеры, переданный initserv аргументом
  `--device=/dev/videoN`.
- camserv выбирает переданную ему конфигурацию потока: формат, ширину, высоту
  и FPS.
- camserv владеет CameraHandle, V4L2-потоком, состоянием камеры,
  IPC-соединениями и подписками клиентов.
- camserv передаёт клиентам кадры в исходном формате camlib, не изменяя их
  байты.
- camserv не обращается к V4L2, ioctl(), mmap() или файловому дескриптору
  камеры напрямую: это зона camlib.
- camserv не декодирует MJPEG, не меняет размер изображения, не применяет
  фильтры и не записывает видеофайлы.
- camserv не ищет камеры автоматически, не управляет правами доступа и не
  поддерживает несколько камер в v1.
- camserv не выдаёт клиентам CameraHandle, FD камеры или указатель на
  MMAP-буфер.

| sys/string | Путь камеры, IPC endpoint и аргументы конфигурации |
| special/camera | Открытие, настройка, запуск, чтение и закрытие CameraHandle |
| special/ipc | IPC endpoint, соединения, сообщения и исходящие очереди |
| sys/eventloop | Один event loop для endpoint, соединений и FD камеры |
| logserv | Запуск, остановка, отказ камеры и ошибки протокола |

## Жизненный цикл

### Запуск

| Параметр | Значение |
| --- | --- |
| Готовая зависимость | logserv |
| Параметры | --device=/dev/videoN, --format=<Yuyv|Mjpeg|Nv12>, --width=N, --height=N, --fps=N |
| Успех | Камера открыта, настроена, поток запущен, созданы event loop и IPC endpoint |
| Ошибка камеры | Записывается в logserv; сервис завершается с PROCESS_EXIT_INITIALIZATION_FAILED |
| Ошибка endpoint или event loop | Камера останавливается и закрывается; сервис завершается |

До создания endpoint сервис обязан проверить, что
`actual_config.max_frame_bytes` вместе с фиксированными полями
CameraFrameEvent не превышает IPC_MESSAGE_MAX_SIZE — 1 МиБ. Это значение
получено из `sizeimage` драйвера через camlib и применимо также к MJPEG.
Неподходящая конфигурация не запускается.

### Остановка и восстановление

При штатной остановке camserv прекращает приём новых клиентов, удаляет FD
камеры и IPC-соединения из event loop, освобождает подписки, вызывает
camera_stop(), затем camera_close() и закрывает IPC server.

При EVENT_HANGUP или EVENT_ERROR сервис вызывает camera_dequeue_frame() до
получения DeviceLost, отправляет подписчикам camera.device_lost, закрывает
CameraHandle и завершает процесс. initserv запускает сервис заново по своей
политике.

После перезапуска все подписки прекращаются. Клиенты должны заново подключиться
и вызвать camera.subscribe.

### Состояния сервиса

| Состояние | Допустимые действия | Переходы |
| --- | --- | --- |
| Starting | Открытие и настройка камеры, создание event loop и endpoint | Ready, Failed |
| Ready | IPC, чтение камеры и публикация кадров | Stopping, Failed |
| Stopping | Освобождение ресурсов | Stopped |
| Failed | Новые операции не принимаются | Завершение процесса |

## Владение ресурсами

| Ресурс | Владелец | Открытие | Освобождение |
| --- | --- | --- | --- |
| IpcServerHandle | camserv через ipclib | При успешном запуске | При остановке |
| IpcConnectionHandle и подписка | camserv | При accept | При отключении клиента или остановке |
| CameraHandle | camserv через camlib | При запуске | При DeviceLost или остановке |
| FD камеры | CameraHandle | Вместе с камерой | Только через camera_close() |
| CameraFrame | camserv временно | После FrameReady | Сразу после копирования кадра в IPC-очереди через camera_frame_release() |

## IPC-контракт

### Клиенты и доступ

| Клиент | Операции | Проверка доступа |
| --- | --- | --- |
| Доверенное нативное приложение | camera.get_info, camera.subscribe, camera.unsubscribe | Внутренний endpoint v1 |
| Графическая оболочка, если понадобится | Те же операции | Внутренний endpoint v1 |

В v1 ipclib не предоставляет идентичность IPC-клиента. Поэтому endpoint camserv
является внутренним контрактом доверенных компонентов, а не публичным
интерфейсом для произвольных процессов.

### Операции

Числовой wire-контракт v1 согласован для этой реализации. Все целые поля
payload кодируются little-endian; `ErrorCode` кодируется как `u32`.

| message_type | Направление | Payload |
| --- | --- | --- |
| 1, camera.get_info | Клиент → сервис | Пустой |
| 2, camera.get_info_result | Сервис → клиент | `u32 error`, `u8 state`, 20 байт config |
| 3, camera.subscribe | Клиент → сервис | `u16 protocol_version` |
| 4, camera.subscribe_result | Сервис → клиент | `u32 error` |
| 5, camera.unsubscribe | Клиент → сервис | Пустой |
| 6, camera.unsubscribe_result | Сервис → клиент | `u32 error` |
| 7, camera.ready | Сервис → клиент | 20 байт config |
| 8, camera.frame | Сервис → клиент | `u64 sequence`, `u64 monotonic_timestamp_ns`, `u32 data_size`, байты кадра |
| 9, camera.device_lost | Сервис → клиент | `u32 reason` |
| 10, camera.error | Сервис → клиент | `u32 error`; ответ на неизвестный либо серверный тип от клиента |

Wire-config состоит из пяти `u32` в порядке `format`, `width`, `height`,
`frames_per_second`, `max_frame_bytes` (20 байт). Wire-значения формата:
`1=Yuyv`, `2=Mjpeg`, `3=Nv12`; значения C ABI библиотеки в payload не
копируются. `state=1` означает Streaming, `state=0` — Unavailable. Когда
Streaming недоступен, 20 байт config нулевые. Endpoint публикуется только
после запуска потока, поэтому обычный успешный `get_info` возвращает
`state=1`. Неподдерживаемая версия подписки даёт `CORE_UNSUPPORTED`, неверный
размер — `CORE_INVALID_ARGUMENT`. При `DeviceLost` событие передаёт
`CORE_IO_ERROR`, поскольку camlib не выдаёт отдельную причину. Повреждённый
IPC-кадр закрывает соединение на уровне ipclib; неизвестный тип получает
`camera.error` с `CORE_INVALID_ARGUMENT`.

| Операция | Запрос | Успешный ответ | Назначение |
| --- | --- | --- | --- |
| camera.get_info | CameraGetInfoRequest | CameraGetInfoResult | Возвращает состояние и фактическую конфигурацию камеры |
| camera.subscribe | CameraSubscribeRequest | CameraSubscribeResult | Создаёт подписку соединения на поток кадров |
| camera.unsubscribe | Пустой payload | CameraUnsubscribeResult | Удаляет подписку |

### События

| Событие | Получатели | Данные | Когда отправляется |
| --- | --- | --- | --- |
| camera.ready | Новый подписчик | CameraReadyEvent | После успешной подписки |
| camera.frame | Активные подписчики | CameraFrameEvent | Получен FrameReady |
| camera.device_lost | Активные подписчики | CameraDeviceLostEvent | Камера отключена или поток потерян |

### Типы сообщений

| Тип | Поля | Ограничения | Назначение |
| --- | --- | --- | --- |
| CameraGetInfoResult | ErrorCode error, u8 state, CameraStreamConfig config | Конфигурация определена только в состоянии Streaming | Состояние и параметры камеры |
| CameraSubscribeRequest | u16 protocol_version | Только версия 1 | Запрос подписки |
| CameraSubscribeResult | ErrorCode error | CORE_OK при успехе | Результат подписки |
| CameraUnsubscribeResult | ErrorCode error | CORE_OK при успехе | Результат отписки |
| CameraReadyEvent | CameraStreamConfig config | Фактическая конфигурация потока | Метаданные перед началом кадров |
| CameraFrameEvent | u64 sequence, u64 monotonic_timestamp_ns, u32 data_size, u8[data_size] data | data_size не превышает actual_config.max_frame_bytes и 1 МиБ с учётом остальных полей | Один необработанный кадр |
| CameraDeviceLostEvent | ErrorCode reason | Причина отказа камеры | Уведомление об остановке потока |

## Контракты

1. Все ошибки передаются как ErrorCode из libcore; CORE_OK — единственный
   успешный результат.
2. Камера открывается, настраивается и запускается один раз при старте camserv.
3. Один IPC-клиент может иметь только одну подписку.
4. После camera.subscribe сервис сначала отправляет camera.ready, затем кадры.
5. При EVENT_READABLE сервис вызывает camera_dequeue_frame() до NoFrame.
6. Каждый CameraFrame сериализуется в IPC payload и ровно один раз возвращается
   через camera_frame_release().
7. Буфер камеры, указатель на его память и его FD никогда не передаются
   клиенту.
8. Если очередь медленного клиента переполнена, закрывается только его
   IPC-соединение; поток камеры и остальные клиенты продолжают работу.
9. Если драйвер вернул кадр больше actual_config.max_frame_bytes либо лимита
   IPC, camserv не сериализует его, записывает ошибку, сразу возвращает буфер
   через camera_frame_release() и продолжает захват. Такой кадр не доставляется
   ни одному клиенту.
10. camserv не изменяет format, width, height, FPS и байты кадров после запуска.

## Потоковая модель и асинхронность

camserv v1 однопоточный. Один поток владеет event loop, CameraHandle, IPC
server, всеми клиентскими соединениями и подписками.

При готовности FD камеры сервис получает кадры до NoFrame. Каждый готовый кадр
копируется в исходящие IPC-очереди активных подписчиков, после чего сразу
возвращается драйверу. Отдельных рабочих потоков, очереди обработки видео и
блокирующих операций в v1 нет.

## Конфигурация и постоянные данные

| Данные | Источник | Владелец | Действие при ошибке |
| --- | --- | --- | --- |
| Путь камеры | Аргумент --device, заданный initserv | initserv | camserv не запускается |
| Конфигурация потока | Аргументы --format, --width, --height, --fps | initserv | camserv не запускается |
| Подписки и состояние камеры | Память процесса | camserv | Теряются при перезапуске |

Постоянное хранение, автопоиск камер, запись видео и восстановление подписок
между перезапусками в v1 отсутствуют.

## Логирование и наблюдаемость

camserv пишет в logserv запуск и применённую конфигурацию, штатную остановку,
ошибку открытия или настройки камеры, DeviceLost и ошибки IPC-протокола.

## Ошибки

| ErrorCode | Когда возвращается клиенту |
| --- | --- |
| CORE_INVALID_ARGUMENT | Payload имеет неверный размер или неизвестный тип сообщения |
| CORE_INVALID_STATE | Повторная подписка или отписка без подписки |
| CORE_UNSUPPORTED | Неподдерживаемая версия, формат или конфигурация превышает лимит IPC |
| CORE_OUT_OF_MEMORY | Нельзя создать подписку или поставить событие в очередь |
| CORE_IO_ERROR | Повреждённый IPC-кадр или ошибка IPC-соединения |

Ошибки открытия, настройки и отказ камеры не являются ответом на подписку:
они записываются в logserv, а DeviceLost передаётся событием
camera.device_lost.

## Ограничения версии

- Только одна камера и один поток захвата.
- Только фиксированная конфигурация, заданная при запуске.
- Нет изменения конфигурации через IPC.
- Нет доступа приложений к FD камеры, shared memory или zero-copy передачи
  кадров.
- Нет декодирования, преобразования формата, фильтров, фото- и видеозаписи.
- Нет аутентификации IPC-клиентов.
