## Описание

initserv — первый системный сервис и владелец жизненного цикла нативных
компонентов платформы. Он запускает зарегистрированные System Services,
сохраняет их ProcessHandle, обнаруживает завершение дочерних процессов и
применяет политику перезапуска.

initserv не выполняет работу сервисов: не пишет журналы, не читает устройства,
не запускает произвольные ELF-файлы и не обслуживает приложения.

## Имя сервиса

| Поле | Значение |
| --- | --- |
| Идентификатор | initserv |
| Исполняемый файл | initserv |
| Владелец запуска | Начальный процесс платформы |
| IPC endpoint | Не предоставляет в v1 |
| Версия протокола | Не определена в v1 |

## Ответственность и границы

- initserv владеет списком зарегистрированных компонентов платформы и их
  ProcessHandle.
- initserv запускает только компоненты из собственного статического реестра
  через process_start. Запуск пути, переданного сторонним клиентом, запрещён.
- initserv запускает logserv первым, затем остальные включённые сервисы.
- initserv периодически вызывает process_poll для каждого дочернего процесса,
  освобождает завершённый ProcessHandle и применяет политику перезапуска.
- initserv передаёт сервису только согласованные аргументы запуска и не
  изменяет его IPC-протокол или внутренние ресурсы.
- initserv не ждёт неподтверждённую «готовность» произвольного сервиса:
  существующие нижние контракты определяют запуск процесса, но не определяют
  общий протокол readiness.
- initserv не получает IPC-команды от приложений и не является менеджером
  жизненного цикла bytecode-приложений; это будущая граница appserv и VM.

## Зависимости

| Зависимость | Использование |
| --- | --- |
| sys/process | process_start, process_poll и process_terminate для дочерних сервисов |
| sys/event | Таймер периодического мониторинга ProcessHandle |
| sys/time | Интервал и задержка повторного запуска |
| sys/thread | ThreadId собственной пробной записи в logserv |
| special/ipc | Только для проверки готовности logserv через его log.submit после запуска |
| logserv | Принимает записи initserv после успешного запуска logserv |

initserv не использует logserv до подтверждённой доступности его endpoint.
Ошибки самого initserv до этого момента передаются только кодом завершения
родительскому окружению.

## Жизненный цикл

### Реестр сервисов и порядок запуска

Реестр является статическим массивом ServiceSpec, скомпилированным вместе с
initserv. Каждая запись содержит идентификатор, ProcessLaunch, флаг enabled,
критичность и политику перезапуска. Он является единственным источником
компонентов, разрешённых process_start.

| Порядок | Сервис | Условие | Политика |
| --- | --- | --- | --- |
| 1 | logserv | Всегда включён | Критичный, перезапускать |
| 2 | appserv | Включён в реестре | Критичный, перезапускать |
| 3 | IOserv | Включён в реестре | Перезапускать |
| 4 | locationserv | Включён в реестре | Перезапускать |
| 5 | camserv | Включён в реестре | Перезапускать |

initserv запускает logserv и проверяет, что его endpoint принимает
log.submit_result с CORE_OK для собственной записи запуска. Только после этого
он запускает остальные включённые сервисы в указанном порядке.

Успешный process_start для остальных сервисов означает только создание
процесса, а не готовность его предметного API. Когда servicelib определит
единый readiness-протокол, initserv должен будет ожидать его перед запуском
зависимых сервисов.

### Мониторинг и перезапуск

Один таймер event loop с периодом 1000 ms вызывает process_poll для каждого
активного ProcessHandle. При завершении process_poll освобождает handle и
возвращает ProcessExitStatus.

Для сервиса с политикой «перезапускать» initserv создаёт одноразовый таймер:
первая задержка 1000 ms, каждая следующая удваивается до 30000 ms. После
успешного запуска задержка сбрасывается до 1000 ms. Сервис не перезапускается,
пока его предыдущий ProcessHandle не завершён через process_poll.

Если logserv не удаётся запустить или подтвердить его доступность, initserv
переходит в Failed и завершает работу с PROCESS_EXIT_INITIALIZATION_FAILED.
Отказ некритичного сервиса журналируется, но не останавливает уже работающие
сервисы.

### Остановка

Внутренний переход в Stopping прекращает таймеры перезапуска. Initserv вызывает
process_terminate для активных дочерних процессов в обратном порядке запуска:
camserv, locationserv, IOserv, appserv, logserv. Затем он вызывает
process_wait для каждого оставшегося ProcessHandle и освобождает его.

В v1 не определено, кто переводит initserv в Stopping: обработка системного
выключения и сигналов потребует отдельного контракта Syscall Wrappers.

### Состояния сервиса

| Состояние | Допустимые действия | Переходы |
| --- | --- | --- |
| Starting | Создание event loop, запуск и проверка logserv | Running, Failed |
| Running | Мониторинг детей, запуск включённых сервисов и их перезапуск | Stopping, Failed |
| Stopping | Завершение детей и освобождение ProcessHandle | Stopped |
| Failed | Новые сервисы не запускаются | Завершение процесса |

## Владение ресурсами

| Ресурс | Владелец | Создание | Освобождение |
| --- | --- | --- | --- |
| ServiceSpec и ProcessLaunch | initserv | До запуска из статического реестра | При завершении initserv |
| ProcessHandle каждого сервиса | initserv | После process_start | Только process_poll или process_wait |
| EventLoopHandle и таймеры | initserv | При запуске | При остановке |
| Временное IPC-соединение с logserv | initserv | Проверка logserv | После получения результата или ошибки |

ProcessHandle остаётся во владении initserv до завершения дочернего процесса.
Initserv не передаёт его другому сервису и не вызывает process_poll либо
process_wait из другого потока.

## IPC-контракт

В v1 initserv не предоставляет IPC endpoint и не принимает команды от
приложений. Единственный IPC-клиентский сценарий — краткое подключение к
logserv для проверки готовности после его запуска и последующего
журналирования собственных событий.

## Контракты

1. Все операции с дочерними процессами выполняются только через libprocess.
2. process_start получает только ProcessLaunch из статического реестра
   initserv; произвольный исполняемый файл или аргументы IPC-клиента не
   допускаются.
3. Каждый успешно полученный ProcessHandle завершается ровно одним
   process_poll или process_wait после остановки ребёнка.
4. ProcessHandle применим только к дочернему процессу initserv; сервис не
   пытается наблюдать чужие PID.
5. process_terminate только отправляет SIGTERM. Initserv всегда выполняет
   process_wait, прежде чем завершить собственный процесс.
6. Все изменения реестра, ProcessHandle и таймеров выполняются одним
   потоком-владельцем event loop.
7. Невозможность запустить или подтвердить logserv критична; она запрещает
   запуск следующих сервисов.
8. Невозможность запустить другой сервис не меняет состояние уже запущенных
   сервисов и не запускает его зависимости повторно.
9. Initserv не объявляет сервис «готовым» только по существованию процесса,
   кроме специальной проверки logserv, определённой этим документом.

## Потоковая модель и асинхронность

Initserv v1 однопоточный. Один поток владеет EventLoopHandle, ProcessHandle,
таймерами мониторинга и временным IPC-соединением с logserv.

Процессы не ожидаются в event loop блокирующим process_wait: штатный
мониторинг выполняется только process_poll по таймеру. Process_wait допускается
только в состоянии Stopping, когда initserv намеренно ожидает завершения уже
остановленных детей.

## Конфигурация и постоянные данные

| Данные | Источник | Владелец | Действие при ошибке |
| --- | --- | --- | --- |
| Реестр ServiceSpec | Статическая конфигурация initserv | initserv | Некорректная запись запрещает запуск до исправления сборки |
| Аргумент logserv --log-path | Статическая запись logserv | initserv | Ошибка logserv переводит initserv в Failed |
| Аргументы устройств IOserv | Статическая запись IOserv | initserv | IOserv сам журналирует недоступное устройство |
| Состояние перезапуска | Память процесса | initserv | Теряется при перезапуске initserv |

Файловое редактирование реестра, установка пакетов и запуск компонентов,
которых нет в реестре, в v1 отсутствуют.

## Логирование и наблюдаемость

После подтверждения logserv initserv отправляет записи о запуске, завершении и
перезапуске каждого сервиса, его ProcessExitStatus и переходе в Stopping. До
готовности logserv такие записи не могут быть
сохранены долговечно.

## Ошибки

| ErrorCode | Когда используется initserv |
| --- | --- |
| CORE_INVALID_ARGUMENT | ServiceSpec содержит пустой путь, недопустимые аргументы или неверную политику |
| CORE_NOT_FOUND | Зарегистрированный исполняемый файл либо endpoint logserv не найден |
| CORE_OUT_OF_MEMORY | Нельзя создать ProcessHandle, event loop или таймер |
| CORE_IO_ERROR | Ошибка запуска дочернего процесса, IPC-проверки logserv или event loop |
| CORE_TIMEOUT | logserv не подтвердил log.submit_result до истечения startup timeout |
| CORE_INVALID_STATE | Операция не допускается в текущем состоянии initserv или службы |

## Ограничения версии

- Нет IPC API для статуса, ручного запуска, остановки или перезагрузки сервиса.
- Нет единого readiness-протокола для сервисов кроме проверки logserv.
- Реестр сервисов статический; нет конфигурационного файла, пакетов и
  пользовательских компонентов.
- Нет обработки системного выключения и сигналов, переводящих initserv в
  Stopping.
- Нет зависимостей между произвольными сервисами: задан только фиксированный
  стартовый порядок.
