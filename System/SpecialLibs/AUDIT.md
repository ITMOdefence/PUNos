# Аудит консистентности — 2026-10-06

Проверены изменения по issue #4 в ветке `feature-special-libs`: ipclib,
loglib, inputlib, camlib, используемые ими libv4l2/libinputdevice и обработка
размеров MemoryBlock в libmem. Проверка включала код, публичные заголовки,
DevDoc, тестовые подмены, Makefile и сценарий CI. Это аудит указанного объёма,
а не заключение об отсутствии ошибок во всей ОС.

| Проблема | Исправление и проверка |

| Повторный запуск после частичного QBUF ставил уже поставленные буферы в очередь повторно | Учёт очереди каждого буфера; проверки 95–96 |
| Драйвер мог выделить больше четырёх буферов, чем помещается в таблицу владения camlib | Используется только запрошенный префикс из четырёх буферов; проверка 94–96 с шестью буферами драйвера |

## Полученные результаты

- Cross-compilation x86_64 Linux: реализации и ABI всех 12 System Libs и
  четырёх Special Libs; семь runtime-программ, включая libmem.
- Шесть полных runtime-наборов прошли в Unicorn с моделируемыми Linux syscalls:
  ipclib, loglib, inputlib, camlib, libv4l2, libinputdevice.
- Проверки libmem 161–166 прошли отдельно; полный набор с fork/сигналами
  этим эмулятором не проверен.
- Все 23 намеренно внесённые регрессии обнаружены ожидаемыми проверками;
  восстановленные версии наборов прошли. Мутации выполнялись во временной копии.
- `git diff --check` проходит.

Статический анализ через Zig/Clang был опробован, но драйвер завершал его
ошибкой FileNotFound. Поэтому успешный статический анализ не заявляется.

## Неподтверждённые проверки

На доступном Windows-хосте отсутствуют рабочие WSL, GNU make/GCC и QEMU.
Моделирование syscall не подтверждает реальный Linux ABI, работу драйверов,
DMA, hot-unplug и загрузку ОС. Перед выпуском нужен зелёный Linux CI с:

```sh
make -C System/SystemLibs check
make -C System/SpecialLibs check
python3 System/SpecialLibs/testing/check_mutations.py
```

Также необходим существующий QEMU boot check и проверка capture/input на
реальных устройствах. Найденные выше опасные дефекты исправлены; утверждать
полное отсутствие критических ошибок без этих проверок нельзя.
